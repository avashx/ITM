# DATA_SOURCES.md - Datasets, Origins, Licences

Every dataset the platform ships with or can consume, its origin, licence, and an
explicit statement of **what is synthetic**.

## 1. Geographic boundaries (vendored in `data/geo/`, real)

| File | Contents | Origin | Licence |
|---|---|---|---|
| `delhi_districts.geojson` | **11 revenue districts** of NCT of Delhi (2011-census-coded, current 11-district structure) | [datta07/INDIAN-SHAPEFILES](https://github.com/datta07/INDIAN-SHAPEFILES) (`STATES/DELHI/DELHI_DISTRICTS.geojson`) | MIT |
| `delhi_assembly.geojson` | **70 assembly constituencies** (AC_NO 1-70 with names, e.g. 1 Narela ... 70 Karawal Nagar) | [datta07/INDIAN-SHAPEFILES](https://github.com/datta07/INDIAN-SHAPEFILES) (`STATES/DELHI/DELHI_ASSEMBLY.geojson`) | MIT |
| `delhi_wards.geojson` | **290 municipal ward/charge polygons** (pre-2022 delimitation incl. NDMC & Cantonment charges) | [DataMeet Municipal_Spatial_Data](https://github.com/datameet/Municipal_Spatial_Data) (`Delhi/Delhi_Wards.geojson`) | CC-BY-SA 2.5 India |
| `delhi_boundary.geojson` | NCT of Delhi outer boundary | [DataMeet Municipal_Spatial_Data](https://github.com/datameet/Municipal_Spatial_Data) | CC-BY-SA 2.5 India |

Refresh from origin anytime: `npm run fetch:geodata`.

**Ward-map caveat (important):** the vendored ward layer is the **pre-2022 (272-ward
era) map with 290 ward/charge polygons**. After the 2022 MCD unification Delhi has
**250 wards**; the authoritative 2022 boundary file is published on OpenCity:
[Delhi MCD Wards Map 2022](https://data.opencity.in/dataset/delhi-wards-information/resource/delhi-mcd-wards-map---2022)
(manual download; drop it in as `data/geo/delhi_wards.geojson` with properties mapped
to `Ward_Name`/`Ward_No` and everything - heatmap, choropleth, seeds - picks it up).
The vendored file is used because it is directly fetchable and licence-clear; ward-level
demo analytics are unaffected, but treat ward *names/numbers* as historical until the
2022 file is dropped in. District (11) and AC (70) layers are current.

## 2. Department & category taxonomy (`data/reference/departments.json`, curated)

15 departments / 39 grievance categories with keyword dictionaries, modelled on the
major complaint heads of **PGMS Delhi** (Public Grievance Monitoring System,
<https://pgms.delhi.gov.in/>) and common Delhi civic-complaint types. Hand-curated for
this project (MIT). SLA defaults follow PGMS norms reported publicly: 7-day first
response, 30-day resolution, 2-3 day SOS handling - configurable via `.env`.

## 3. Service endpoint catalogue (`data/endpoints.json`, researched)

85 public GNCTD/Delhi service URLs compiled 2026-07-07 from official portals, service
directories and current search verification. See [ENDPOINTS.md](ENDPOINTS.md) for the
full table, per-entry verification status, and the re-verification procedure
(`npm run verify:endpoints`).

## 4. Grievance data - **SYNTHETIC by default**

> **There is no real citizen data in this repository.**

The shipped grievance dataset is generated by `scripts/lib/grievance-generator.js`:

- **Labelled end-to-end:** every record has `source: "synthetic"` and a `SYN-`-prefixed
  grievance ID; the UI footer states the data is synthetic.
- **Shaped to be realistic:** PGMS-style categories; weekly seasonality (Monday peak);
  department-specific resolution-time distributions; ~2% SOS / 10% urgent priorities;
  points geolocated *inside real ward polygons* with district/AC assigned by
  point-in-polygon against the real boundary files above.
- **No PII by construction:** no names, addresses, phone numbers or free-text beyond
  template-generated complaint descriptions.
- **Deterministic:** same `--seed` -> same dataset (default seed `20260707`).

The demo seed additionally injects three **outage->complaint-spike scenarios**
(e-District, DJB, MCD) so Module 3 has patterns to detect - these are also synthetic
and documented in `scripts/seed-demo.js`.

## 5. Real data sources you can connect (documented, not bundled)

| Source | What | How to use |
|---|---|---|
| [data.gov.in](https://www.data.gov.in) / [delhi.data.gov.in](https://delhi.data.gov.in) | Open Government Data platform - Delhi catalogue incl. grievance statistics datasets | Register (free) -> API key -> `DATA_GOV_IN_API_KEY`; pull via `https://api.data.gov.in/resource/<id>?api-key=...&format=json`, transform, POST to `/api/grievances/import` (see API_KEYS.md §3) |
| [PGMS Delhi](https://pgms.delhi.gov.in/) | GNCTD's live grievance system | No public API; with departmental access, export and bulk-import. The taxonomy here is designed to align |
| [CPGRAMS](https://pgportal.gov.in/) | GoI grievance portal - DARPG publishes monthly PDF/statistical reports incl. Delhi | Manual extraction -> import; useful for benchmarking volumes |
| [OpenCity Delhi](https://data.opencity.in/dataset?city=Delhi) | Community-curated Delhi datasets (2022 ward map, demographics) | Manual download (see ward caveat above) |
| [Delhi SLDC](https://www.delhisldc.org/) | Real-time Delhi power demand | Monitored as an endpoint; scraping its data is a possible Module 2 enrichment |

## 6. Map tiles (runtime, external)

OpenStreetMap raster tiles (`tile.openstreetmap.org`) under the
[OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/), with
attribution shown on the map. Optional MapTiler/Carto alternatives - see
[API_KEYS.md](API_KEYS.md) §4. Without internet, the map still renders boundaries and
data layers on a blank background.
